# 从零到第一次查看

本页完成一条最小闭环：**严格显式架构项目 → Atlas Package → 本地 API → 浏览器中的角色化页面**。

## 0. 先确认前置条件

| 工具 | 最低要求 | 用途 |
| --- | --- | --- |
| JDK | 21 | 构建 Atlas 与运行 CLI/server；更高版本可用 |
| Maven | 3.9 | 构建 Reactor 和 fixture |
| Node.js | 20 | 运行独立 `atlas-web`；仓库开发建议 Node 22 |
| 被分析项目 | 可访问的本机源码目录 | 供静态分析读取；不提交到 Atlas 仓库 |

先确认 Atlas 本身是健康的：

```powershell
mvn -B verify
npm --prefix ui-layer/atlas-web run check
pwsh ./scripts/verify-structure.ps1
```

这些命令不会分析你的真实项目。它们只验证 Atlas 自己的 Maven、Web、结构和通用 fixture。

## 1. 建立私有 Workspace

不要修改仓库里的模板，也不要把真实路径、归档、内容或运行态导出提交到 Git。

```powershell
New-Item -ItemType Directory -Force workspace/local
Copy-Item workspace/atlas-workspace.example.yaml workspace/local/atlas-workspace.yaml
```

编辑 `workspace/local/atlas-workspace.yaml`，至少填写：

```yaml
schemaVersion: "1.0"
workspaceId: "workspace:my-project"
project:
  id: "project:my-project"
  displayName: "我的业务项目"
sources:
  projectRoot: "C:/absolute/path/to/my-project"
  sourceArchives: []
  intentManifests: []
runtime:
  enabled: false
  observationFiles: []
```

如果你使用 Atlas 注解，先在**被分析项目**中完成一次编译，并把生成的 `META-INF/explicit-architecture-atlas/atlas-intent.json` 填入 `intentManifests`。没有注解也可以运行；只是不易从技术事实自动得出的业务解释会显示为待补充。

`content.root`、`sourceArchives` 与 `runtime.observationFiles` 都是私有配置。当前 CLI 不会自动读取内容包；不要因为写了 `content.root` 就认为业务手册已进入 Package。

## 2. 生成静态 Atlas Package

构建 CLI 后执行 `extract`：

```powershell
mvn -B -pl infra-driving/atlas-cli -am package

java -jar infra-driving/atlas-cli/target/explicit-architecture-atlas-cli-0.0.1.jar extract `
  --workspace workspace/local/atlas-workspace.yaml `
  --package-id package:my-project:2026-08-04 `
  --source-revision git:your-commit-id
```

命令会读取源码、POM 和 Workspace 声明的 Intent Manifest，并把 Package 原子写入：

```text
workspace/local/packages/<URL-safe-base64(packageId)>.atlas.json
```

文件名不是给人阅读的身份；Windows 文件名不能包含 `:`，所以真实 `packageId` 保留在 Package Manifest 中。浏览器和 HTTP API 始终使用你传入的完整 ID，例如 `package:my-project:2026-08-04`。

成功后应检查 CLI 输出：节点、关系、事实数量，以及每个分析器的 coverage。某项显示 `PARTIAL` 或 `NOT_ENABLED` 不是失败；它要求你在解释图谱时保留不确定性。

## 3. 启动本地查询服务

构建并启动 runner：

```powershell
mvn -B -pl ui-layer/atlas-server-bootstrap -am package

java -jar ui-layer/atlas-server-bootstrap/target/explicit-architecture-atlas-server-bootstrap-0.0.1.jar `
  --workspace workspace/local/atlas-workspace.yaml `
  --port 8080
```

它默认只监听回环地址。可在另一个终端确认服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
```

预期得到 `status = UP`。不要直接把这个无认证的 V1 runner 暴露到办公网或公网。

## 4. 启动 atlas-web

另开终端：

```powershell
npm --prefix ui-layer/atlas-web run dev
```

浏览器打开 `http://127.0.0.1:4173`，在页面中填写：

- **Atlas API 地址**：保持默认即可；开发服务器会同源代理到 `127.0.0.1:8080`；
- **Package ID**：输入 `package:my-project:2026-08-04`。

页面会同时读取摘要、业务、运维和专家三种视图。若 Package 不存在，检查 Workspace 路径与 `packageId` 是否完全一致；不要尝试按照 JSON 文件名猜测 ID。

## 5. 可选：导入运行态观测

当你准备好**脱敏的** Axon 离线导出后，把 `runtime.enabled` 设为 `true` 并在 `observationFiles` 中列出文件，再执行：

```powershell
java -jar infra-driving/atlas-cli/target/explicit-architecture-atlas-cli-0.0.1.jar observe `
  --workspace workspace/local/atlas-workspace.yaml `
  --package-id package:my-project:2026-08-04
```

它会替换可过期的 `runtimeOverlay`，不会重写静态图。再刷新 Web 的“运行态”页面即可。状态和导入约束见[运行态与运维处置](05-运行态与运维处置.md)。

## 6. 第一次查看时应验证什么

1. **业务地图**中至少能看到一条领域规则、事件或接口；没有业务解释时，应补 Intent，而不是要求业务人员读类名。
2. **运行态**在未执行 `observe` 时显示“未采集”，而非“全部正常”。
3. **专家模式**中的调用路径只包含有证据的边；空路径并不表示 Atlas 漏画了关系。
4. 源码按钮只有以 `--enable-expert-source` 启动 runner 且 Workspace 声明了 `sourceArchives` 时才可用。

更细的故障排查在[常见问题](09-常见问题.md)。
