# 常见问题

## 为什么 Web 打不开 Package？

按顺序检查：

1. runner 是否在 `http://127.0.0.1:8080/health` 返回 `UP`；
2. `atlas-web` 是否通过 `npm --prefix ui-layer/atlas-web run dev` 启动；
3. 页面中输入的 Package ID 是否与 `extract --package-id` 完全一致；
4. runner 使用的 Workspace 是否和 `extract` 使用的是同一个 `workspace/local/atlas-workspace.yaml`；
5. 不是去猜 `packages/` 下 Base64 文件名；真正身份在 Manifest 里。

## 为什么业务页面没有某条关系？

先打开摘要中的 coverage 和 diagnostics。常见原因是：源码未使用当前分析器能确认的显式写法、调用/泛型/事件类型无法唯一解析、相关适配器未启用，或者该业务意图尚未声明。

不要通过“类名很像”或“按惯例应该有”要求 Atlas 加边。应修正显式代码、补充 Intent，或扩展分析器；在此之前，空关系比错误关系更安全。

## 为什么 `NOT_CAPTURED` 不是 `UNKNOWN`？

`NOT_CAPTURED` 表示 Package 根本没有 Runtime Overlay，无法对任何资产做运行结论。`UNKNOWN` 表示有一次 Overlay，但本批次没有某资产的唯一关联记录。前者没有观测，后者有观测但无法判断；两者都不是成功。

## 为什么事件处理成功，业务页面仍没有更新？

`SUCCEEDED` 只说明最近一次可关联处理完成。再检查：投影目标是否正确、查询条件/权限/缓存是否过滤、数据是否在另一个读模型或租户范围中、所看的 Package/运行观测是否属于同一源码版本。不要仅凭一张成功卡片认定用户必定能看到结果。

## 为什么专家模式不能查看源码？

源码查看需要同时满足：runner 带 `--enable-expert-source`；Workspace `sources.sourceArchives` 非空；资产属于当前 Package；资产本身或唯一的 `REPRESENTS` 代码映射可定位；source JAR 中有相应条目。任何一项不满足都会返回明确错误或不可用状态。它不会根据浏览器提交的路径读取文件。

## 为什么 Package 的 JSON 文件名看不懂？

`packageId` 经 URL-safe Base64 转成文件名，因为 Windows 不允许 `:`。这是跨平台存储策略，不是 ID 丢失。使用 CLI 参数、Manifest 或 HTTP 路径中的原始 Package ID。

## 是否能只用注解、不写严格显式代码？

不能。注解用于补充稳定业务意图，不替代真实路由、命令处理、事件消费、投影写入、表映射和运行状态。Atlas 仍会把注解与源码证据分开；冲突时会暴露，而不会把注解当成最终真相。

## 是否能把 `workspace/local`、source JAR 或观测 JSON 提交到仓库？

不能。它们可能含绝对路径、业务源码、payload、凭据或内部运行信息。仓库只保留无真实信息的 Workspace 模板和通用 fixture；私有输入由部署系统或安全目录提供。

## Maven Plugin 能否直接替代 CLI？

可以用于静态提取。`atlas:extract` 在 Maven `package` 阶段将 Package 写入当前工程的 `target/atlas/packages/`，默认分析 Java 源码、Maven POM 和编译期 `atlas-intent.json`。它不读取操作系统环境、私有 Workspace、运行态观测或秘密，因此不能替代 CLI 的 `observe`、`scenario` 等受控 Workspace 功能。

普通 Plugin 不会包含 Spring、Axon、JPA。若要分析这些技术事实，请在 Maven `<plugin><dependencies>` 中显式加入对应 Atlas adapter；详见[本地开发、构建与发布](../contributors/01-本地开发、构建与发布.md#在被分析工程中使用-maven-plugin)。

## 还需要帮助时应该提供什么信息？

在不泄露私有业务数据的前提下，提供：Atlas 版本、JDK/Maven/Node 版本、`extract`/`observe` 命令、Package ID、`manifest.coverage`、诊断代码、是否启用运行态与专家源码。不要发送 Workspace 绝对路径、token、真实 payload、完整业务源码或 source JAR。
