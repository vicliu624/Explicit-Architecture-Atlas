# 注解、处理器与意图产物

## 结论

Atlas 注解用于表达**代码无法可靠推导的稳定业务意图**，不是让开发者重复描述 Spring、Axon、JPA 或正则实现细节。注解 API 独立成一个零框架依赖 Maven 工件，并使用 `RetentionPolicy.SOURCE`：它只在编译期存在，生成机器可读意图索引，不成为业务系统运行时负担。

技术事实仍由分析器从源码和配置提取。例如：

- `@PostMapping`、控制器方法和 Bean 调用关系由 `atlas-spring-source` 提取；
- `@EventHandler`、`@SagaEventHandler`、`@ProcessingGroup` 和 Axon 配置由 `atlas-axon-source` 提取；
- `@Table`、实体映射和 Writer/DAO 目标由 `atlas-jpa-target-resolver` 提取；
- `Pattern`、guard、`requireTrue`、异常和测试等约束执行证据由 JVM 源码分析器提取。

## 当前可用注解

| 注解 | 目标 | 表达的稳定意图 | 不应在其中重复 |
| --- | --- | --- | --- |
| `@AtlasContext` | 包、类型 | 限界上下文的稳定 ID、业务名称、描述 | Maven 模块名、包扫描规则 |
| `@AtlasAggregate` | 类型 | 聚合业务名称和一致性职责 | Axon 聚合技术配置 |
| `@AtlasConstraint` | 类型、字段、方法、记录组件 | 约束 ID、名称、分类、业务意义和执行点提示 | 可从代码直接推导的重复校验逻辑 |
| `@AtlasEvent` | 类型 | 事件代表的业务事实和关键 payload 语义 | Event Store 表、序列化器配置 |
| `@AtlasProjection` | 类型、方法 | 读模型的业务目的 | JPA 表名、SQL、缓存配置 |
| `@AtlasProcessManager` | 类型 | 跨聚合流程职责和完成条件 | Saga association key、Deadline 具体代码 |
| `@AtlasEndpoint` | 方法 | 外部操作的业务名称和目的 | HTTP method、路由、参数类型 |

`@AtlasConstraint` 的 `kind` 使用受控分类：`REQUIRED`、`IDENTITY_FORMAT`、`NUMERIC_RANGE`、`CROSS_CONCEPT_CONSISTENCY`、`UNIQUENESS`、`STATE_TRANSITION`、`EVENT_PRECONDITION`、`TEMPORAL`、`OWNERSHIP`、`COMPENSATION` 和 `CUSTOM`。

这使“身份格式由正则约束”成为 Atlas 中可解释的领域约束：`expression` 可以保留正则作为专家证据，而 `businessMeaning` 必须写出普通使用者能理解的规则。渲染器默认显示后者，并在专家模式展开前者和其真实执行点。

## 示例

```java
@AtlasAggregate(
    id = "order",
    name = "订单",
    responsibility = "维护订单身份与创建前的一致性规则")
public final class Order {

  @AtlasConstraint(
      id = "order-id-format",
      name = "订单身份格式",
      kind = ConstraintKind.IDENTITY_FORMAT,
      expression = "^[A-Z]{2}-\\d{6}$",
      businessMeaning = "订单编号由两位业务前缀和六位流水号组成。",
      enforcedBy = "OrderId.of")
  public static String orderId(String value) { /* 真实校验代码 */ }
}
```

这里 `businessMeaning` 是必须显式声明的语义；方法、正则、异常和调用点是可验证的技术证据。若二者不一致，Atlas 应同时展示“已声明”和“已推导”的来源，并标记为需要审核，而不是选择一方静默覆盖另一方。

## 编译时产物

`explicit-architecture-atlas-annotation-processor` 在编译结束时生成：

```text
META-INF/explicit-architecture-atlas/atlas-intent.json
```

产物包含 `schemaVersion`、稳定声明 ID、完整注解类型、目标二进制名、成员描述符和保持 JSON 原生类型的属性。它是“明确声明的意图索引”，不试图替代完整 Atlas Package。

```json
{
  "schemaVersion": "1.0",
  "declarations": [
    {
      "id": "intent:AtlasConstraint:order-id-format",
      "annotationType": "io.github.vicliu624.explicitarchitecture.atlas.annotation.AtlasConstraint",
      "assetKind": "DOMAIN_CONSTRAINT",
      "target": {
        "kind": "METHOD",
        "binaryName": "example.Order",
        "memberDescriptor": "orderId(java.lang.String)"
      },
      "attributes": {
        "id": "order-id-format",
        "businessMeaning": "订单编号由两位业务前缀和六位流水号组成。",
        "kind": "IDENTITY_FORMAT"
      }
    }
  ]
}
```

`AtlasIntentManifestReader` 会将该索引与源码分析结果、内容包和运行态观测合并到标准 Atlas Package。处理器不执行网络连接，不读取业务数据库，也不访问本机 Workspace。

## Maven 配置

业务项目需要普通依赖注解 API，并将处理器放在编译器处理器路径中：

```xml
<dependencies>
  <dependency>
    <groupId>io.github.vicliu624.explicitarchitecture</groupId>
    <artifactId>explicit-architecture-atlas-annotations</artifactId>
    <version>${atlas.version}</version>
  </dependency>
</dependencies>

<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <configuration>
        <annotationProcessorPaths>
          <path>
            <groupId>io.github.vicliu624.explicitarchitecture</groupId>
            <artifactId>explicit-architecture-atlas-annotation-processor</artifactId>
            <version>${atlas.version}</version>
          </path>
        </annotationProcessorPaths>
      </configuration>
    </plugin>
  </plugins>
</build>
```

仓库中的通用 fixture 已使用这份配置。它既验证处理器能工作，也防止示例意外依赖某个真实业务项目。

## 注解设计约束

新增注解时必须满足以下条件：

1. **有稳定 ID。** 不能以类名或路由作为唯一身份，因为重构后内容包与历史快照仍需关联。
2. **表达业务语言。** `name`、`responsibility`、`purpose`、`businessMeaning` 面向非开发读者，而不是缩写技术术语。
3. **保持零框架依赖。** `atlas-annotations` 不得依赖 Spring、Axon、Maven、JPA、Jackson 或领域核心模型。
4. **保持编译期性质。** 默认使用 `SOURCE`；只有经过专门 ADR 的运行时扩展才允许改变保留策略。
5. **不复制可推导事实。** 框架注解、路由、表名、处理器组、正则、SQL 等由分析器补齐；确有人工解释价值时引用它们的稳定证据锚点。
6. **支持证据冲突。** 注解只声明意图，不能压制源码或运行态的真实结果。

当没有注解时，Atlas 仍应尽可能提取技术事实，并将“业务解释待补充”明确展示。这保证采用 Atlas 是渐进式的，不要求一次性注解全部系统。
